# Adversarial review: C++ examples and demos (2026-11-05)

This reviews every example (01–13z) and presentation demo (Demos 1–6): about 25.7k lines, one
`main.cpp` each, each built by copying the one before. It was written for re-implementing them
efficiently and readably on shared classes (D34).

**How to read the references:** `13e:535` means `exercises/cpp/legacy/13e_Kinect_Room_Scan_Autosave/main.cpp`,
line 535, and `D4:465` means Demo 4. Line numbers are from commit 3cd8485, before the move to `legacy/`;
the move didn't change any line. Items marked ★ were checked by reading the code a second time.

## 2. Speed: the biggest wins

- **Each box's depth median scans all 217k depth pixels** (02:275, 04:227, 05:296, 06:296, 08b:285/359, D3:638), and 05c:474 does it per track, per frame, at 30 fps. Build a colour x/y table per depth pixel once per frame, then visit only the pixels inside each box (`BoxDepthSampler`).
- **`FuseScans` is voxels × scans** (13e:1199-1229): about 400M projections for 30 scans. Integrate along each scan's pixels instead, or first clip the grid to what each scan could see.
- **The shortlist re-stacks every descriptor and brute-force matches it** for each placement and every 500 ms in CheckLive (13e:793-807, 1030). Keep a persistent `DescriptorIndex`.
- **PlaceScan rebuilds its target from every earlier scan** (13e:899-919): O(n²) over a session. Keep one thinned room cloud keyed by cube.
- **Viewers compute 4 sin/cos per point** (08:87, D1:99, D4:130, D6:195; 13c+ already compute them once) and allocate a new image and z-buffer every frame. Compute the rotation once per frame and reuse the buffers.
- **Autosave runs on the UI thread** (13e:2194): about 11 MB of BMPs plus features.yml per scan. That's seconds on a Pi's SD card.
- Whole `Scan`s are copied in Export, FinishRoom and 13z's BuildObj/BuildPly (4–5 MB each): use `const Scan*`.
- Smaller ones:
  - `cv::format` runs per vertex in the OBJ/PLY writers;
  - RANSAC scores every point on every try (06b/06c/D3 every frame) with no early stop;
  - `ColorForId` runs a `cvtColor` per track per draw;
  - ORB and CLAHE objects are recreated on every call (13e:546, 591, 599).

### Swapping the detector model

A different YOLO, or one you trained yourself, needs no code change:
- `modelPath` and `inputSize`, as today (`yolo26n.onnx` / `yolo26n_320.onnx`).
- `namesPath`: a text file next to the model, one class name per line. Ultralytics keeps the names
  in the ONNX metadata, which OpenCV DNN can't read. For your own model, write the names from the
  training `data.yaml` in the same order.
- `layout`: `EndToEnd` for today's export (`nms=False`, 1x300x6: box, score, class) or `Classic` for
  older exports (1x(4+classes)x8400, then NMS).
- Examples use the names file's count, never 80, and look up "person" by name, never as id 0.

A second backend (NCNN, Roadmap lever 3) is a sibling file, `detector_yolo_ncnn`, with the same
`detect()` signature. It gets a shared base class only once an example has to choose one at run time.

## 6. Order of work

Each step ports 13e, 13z and Demos 4/6 first, because they are the most used and the most copied.

1. `source_freenect2` + `DepthCamera`, with the mirror fix and room format 2. Old rooms are mirrored on load: x → −x, R → S R S.
2. `Pose`, `Plane`, the medians.
3. `RoomFolder` (bugs 3–5).
4. `OrbitView` / `PointRenderer`.
5. `TsdfVolume`, BuildRoom.
6. `detector_yolo_opencvdnn`, `Tracker`. (`BoxDepthSampler` was done first, as a trial: `spotter/src/depth.cpp`. It matches 05c's `SampleMeters` on 4,000 synthetic boxes, at 2.0 ms instead of 5.1 ms per frame with 5 boxes.)

**Checks:** each module gets one small self-check program on synthetic data, like the D29/D33
tests: a raycast room through the real functions. For the room modules, also byte-compare 13z's
`points.ply` with 13e's.
